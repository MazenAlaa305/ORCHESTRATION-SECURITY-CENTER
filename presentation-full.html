02 · The SME Security Gap

Caught in a three-way trap

Small and medium-sized enterprises are attacked as often as large enterprises — but lack the budget, the tooling, and the staff to defend.

No security team

A typical 200-person SME has zero dedicated security headcount. The IT generalist handles antivirus and crosses their fingers.

# reality: 0 SOC analysts 0 AppSec engineers 1 sysadmin · wears 7 hats

Fragmented tools

SMEs stitch together free scanners, an antivirus, a firewall log viewer. No shared context. No single source of truth.

# typical stack: Nmap · network scan Nuclei · vuln templates ELK · log search …all isolated, no shared brain

Alert fatigue

Every tool screams in its own language. Thousands of raw findings per week. No one qualified to triage. Real attacks hide in the noise.

# industry studies: 67% of SMEs ignore alerts entirely under-staffed teams burn out in 18 months

The consequence

277 days · mean dwell time (IBM Cost of a Breach 2023) our target · < 24 hours via prioritized queue

03 · Design Principles

Three pillars · non-negotiable

Every architectural decision we made traces back to one of these three.

Deterministic scoring

The risk formula is a Python file — fully auditable, fully reproducible. A professor or an auditor can walk through it line by line. No black-box LLM in the path that produces the number.

score = (vuln × conf + port) × asset × exposure

AI-assisted, not AI-dependent

The platform works without an API key via a built-in demo mode. Gemini upgrades the experience — better explanations, better validation — but does not gate the core flow.

# config.py DEMO_MODE = True # offline LLM_OPTIONAL = True

Container-native

One docker compose up command. Six containers. ~1.4 GB RAM. Runs on a 16 GB laptop. SME-friendly in practice, not just in slides.

$ docker compose up -d ✓ 6 containers · 1.4 GB ✓ ready in < 60s

04 · Conceptual Foundation

Orchestration & Automation

Two words our entire platform is built on — and the difference between a script and a system.

Automation

Executing a single repetitive task without human input.

$ cron 0 2 * * * → nmap -sV 10.10.10.5 # Run a port scan every night at 2 AM.

Orchestration

Coordinating multiple automated tasks into an intelligent workflow that adapts to outcomes.

nmap → port 445 open ↳ launch SMB-only Nuclei templates ↳ validate with LLM agent ↳ score & notify
Signal → ActionThousands → 5Raw alerts compressed to prioritized actions

06 · Async Plumbing

FastAPI → Celery → Redis → Worker

No request blocks. The user gets a task ID in < 200 ms. The pipeline runs out-of-band and streams progress back.

06 · Agent Layer

Four agents · one BaseAgent contract

Each agent runs in turn. Every action is logged to a SHA-256 hash-chain — tamper-evident audit trail.

DiscoveryAgent

Wraps Nmap. Parses XML into our Asset model. Outputs the host/port/service graph.

tool: nmap input: target output: Asset[]

ExploitAgent

Drives Nuclei. Template selection matches detected services to template tags — the orchestration logic.

tool: nuclei input: Asset[] templates: by tag

InfrastructureAgent

Config-level checks. "Is TLS configured correctly?" "Is Redis password-protected?" No external network calls.

tool: custom probes input: Asset[] output: ConfigFinding[]

IntelligenceAgent

Only agent that talks to Gemini. Sandboxed · rate-limited · budget-capped. Confirms exploitability.

tool: gemini-1.5 guard: token budget fallback: rule-based

Hash-chained audit log

Every AgentLog row contains prev_hash + content, hashed with SHA-256. Modifying any past entry breaks the chain.

log_n.hash = SHA256( log_n.content + log_n-1.hash )

06 · Live Channel

Real-time · pub/sub → WebSocket → React

One WebSocket per browser. Cache invalidation wired through React Query.

Three layers

1
Celery worker publishes events to a Redis pub/sub channel during pipeline execution.
2
FastAPI WebSocket at /ws/events subscribes on behalf of each browser session.
3
RealTimeContext (React) owns the single connection. Every component subscribes through it — not five duplicate sockets.

Cache invalidation

A RISK_UPDATE message invalidates the relevant React Query key. The component refetches automatically — no manual setState.

Message types

RISK_UPDATE

Recalculates the gauge. Refetches the Action Center. Invalidates risk-summary query.

LOG_STREAM

Appends to the live log panel inside the active scan view. Throttled client-side.

SCAN_PROGRESS

Advances the four-stage pipeline indicator. Pulse animation per stage transition.

06 · Optional Layer

SIEM & SOAR · feature-flagged

Three more containers under --profile full. The platform degrades gracefully if any are absent.

Wazuh 4.7.2

Host-based SIEM agent + manager. Watches OS logs, detects brute-force, file integrity changes, rootkits.

# events: brute-force ssh file-integrity drift rootcheck failures

Elasticsearch 8.11.1

Stores Wazuh alerts. The Unified Inbox queries it for the SIEM stream. Indexed by @timestamp + agent_name.

# indices: wazuh-alerts-* osc-app-logs-*

n8n · SOAR

Consumes Elasticsearch events. Orchestrates response workflows: brute-force → Slack alert + auto-rescan.

# workflow: on: brute-force do: slack + scan

Graceful degradation: if the SIEM containers are not started, the Unified Inbox shows zero SIEM events instead of crashing. SIEM is optional, not mandatory.

06 · Self-Posture

We hold ourselves to the same bar

The platform that scans targets must itself be defensible. Five layers, no skipped corners.

Auth

JWT tokens · bcrypt password hashing · refresh-token rotation.

Secrets

Fernet symmetric encryption for stored credentials · keys in env vars · never committed.

Scope

Per-target allowlist · misconfigured scan cannot leak outside the agreed perimeter.

LLM safety

Token budget · rate limit · prompt-injection-aware sanitization on input.

Containers

Non-root user · read-only root FS · minimal base images · pinned versions.

We also run our own platform against itself in CI — the OSC scans the OSC. Self-application is the strongest correctness test.

07 · Lessons Learned

Challenges we faced · and overcame

Three engineers · three honest stories about the walls we hit and how we got past them.

Stateful E2E testing

Mazen Alaa

Problem: Each pipeline stage's output is the next stage's input. Celery makes everything asynchronous. Tests were flaky and slow.

Solution: Deterministic seed targets + scan replay fixtures. We record one real scan, replay the recorded responses in tests. Fast, reproducible, no network.

@pytest.fixture def replay_scan_a3f9c7(): return load("fixtures/...")

11-engineer API drift

Youssef Ali

Problem: 11 engineers committing to one FastAPI app. Someone renames a field, three frontends break. Constant contract drift.

Solution: OpenAPI snapshot test in CI on every PR. Schema change without matching version bump → PR is blocked. Forced communication.

openapi-diff snapshot schema vs main → block on breaking change

32 GB stack · 16 GB laptops

Omar Kapil

Problem: Full stack with SIEM + OpenVAS wants 32 GB RAM. Most team laptops have 16. We could not develop on our own machines.

Solution: start-lite.sh profile · 6 core containers · ~1.4 GB. Feature-flagged graceful degradation. Same config we expect SMEs to use.

$ ./start-lite.sh 6 containers · 1.4 GB SIEM=off · OpenVAS=off
