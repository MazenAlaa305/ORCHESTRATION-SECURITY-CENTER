# .env — Documentation

## File Purpose

The root-level `.env` file provides environment variable overrides for **local development**. When running the backend directly (outside Docker), Python's `pydantic-settings` library reads this file automatically to populate the `Settings` object defined in `app/core/config.py`. In the Docker Compose deployment, variable injection is done directly in `docker-compose.yml`, so this file is not used inside containers.

## Key Variables Defined

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | SQLAlchemy connection string. Defaults to `sqlite:///./test.db` for local dev; points to PostgreSQL in production. |
| `REDIS_URL` | Connection string for the Redis broker used by Celery. |
| `GEMINI_API_KEY` | API key for Google Gemini. Enables LLM-powered scan validation and AI advisory features. If absent, agents operate in deterministic demo mode. |
| `OPENVAS_HOST` | Hostname of the OpenVAS GVM service. |
| `OPENVAS_PORT` | Port for the GMP (Greenbone Management Protocol) listener, typically `9390`. |
| `OPENVAS_USER` / `OPENVAS_PASSWORD` | Credentials for the OpenVAS admin account. |
| `ELASTICSEARCH_URL` | Base URL for the Elasticsearch SIEM instance. |
| `WAZUH_API_URL` / `WAZUH_API_USER` / `WAZUH_API_PASSWORD` | Connection details for the Wazuh REST API. |
| `N8N_WEBHOOK_URL` | Base URL for triggering n8n SOAR automation webhooks. |

## Security Notes

- This file is listed in `.gitignore` and must never be committed to version control, as it contains credentials.
- In a production deployment, secrets should be injected via a secrets manager (e.g., AWS Secrets Manager, HashiCorp Vault) rather than a flat `.env` file.

## Dependencies

- **Reads by**: `backend/app/core/config.py` via `pydantic-settings`.
- **Overridden by**: `docker-compose.yml` environment block for containerized deployments.
