## 1. Industry Standards Baseline (applied during Phases 2–6)

### 1.1 Full-Stack QA & Backend→Frontend Pipelines
- **ISTQB testing taxonomy.** Every change must sit in one layer: unit (pure logic), integration (service + DB), contract (OpenAPI schema drift guard), E2E (Playwright/React Testing Library), exploratory (pentester persona).
- **OpenAPI as single source of truth.** FastAPI already exposes `/openapi.json`; the frontend client currently hand-rolls request shapes in [frontend/src/services/api.js](frontend/src/services/api.js). Target: frontend types generated from the spec, diff checked in CI.
- **Real-time reliability.** Baseline for WebSocket pipelines: heartbeat ≤ 30 s, exponential reconnect backoff, monotonic sequence numbers, REST catch-up endpoint. Current platform has heartbeat (25 s) and backoff but is missing sequence numbers — and, critically, the broadcast function name is wrong (see defect W-001).
- **Observability triad.** JSON structured logs, request-id propagation, RED metrics (rate/errors/duration). Current: structured logs ✓; request-id ✗; RED ✗.

### 1.2 Cybersecurity Dashboard UI/UX
- **Reference dashboards.** Elastic Security, Wazuh, OpenVAS GSA, MITRE ATT&CK Navigator.
- **Cognitive-load rules.**
  - Max 7 default columns in any finding table.
  - ≤ 5 semantic colours app-wide for severity (Critical / High / Medium / Low / Info). Avoid gradients and rainbow chips.
  - Progressive disclosure: advanced knobs collapsed behind "Advanced".
  - Density tiers: Comfortable (default) vs Compact (toggle).
  - Recognition over recall: never force users to remember a previous target — offer it.
- **Alert-fatigue countermeasures.** Deduplicate (already wired via `finding_dedup`), default filter `status != closed AND severity >= medium`, group by asset/CVE.
- **Accessibility.** WCAG 2.2 AA, 4.5:1 contrast, keyboard-only navigation, colour never the only signal.

### 1.3 Isolated Pentest Lab SOPs
- OffSec / SANS GPEN: the lab subnet must be unable to egress to the internet or to the user's LAN.
- Docker primitives: `internal: true` on lab networks; scanner is the only bridge with two NICs.
- Host-level firewall rules must survive reboot.

### 1.4 Vulnerability Management & Scanner-Accuracy Auditing
- Golden-dataset approach: every planted vulnerability declared with CVE/CWE/severity/expected signature. Precision/recall matrix on each full run.
- Baseline targets: Recall ≥ 0.95 on Critical/High, overall Recall ≥ 0.90, Precision ≥ 0.80.

### 2.4 Data contract diff (representative — blockers only)

| Surface | Backend shape | Frontend shape | Drift |
|---|---|---|---|
| `GET /scans/` → ScanSummary | `{id: UUID-string, started_at: ISO, ...}` | `ScanHistory` expects `b.id - a.id` numeric diff (line 16) | **Blocker**: UUID subtraction → NaN → no sort applied. |
| WS event envelope | `{type, payload}` via Redis | Client expects `{type, payload}` | **Blocker**: middle hop `broadcast_event()` does not exist on `ConnectionManager` — events never delivered. |
| `POST /scans/{id}/stop` | sets status to `FAILED` | UI expects "stopped" semantic | **High**: false-failure labelling. |
| `GET /lab/*` | no `Depends(get_current_user)` | frontend sends JWT anyway | **Medium**: inconsistency — lab endpoints are public-by-default. |
| `GET /findings.count()` | joined query, severity enum compared to string | — | **Low**: count may double-count in joined path, and `Finding.severity.desc()` on an enum is DB-driver-dependent ordering. |
| `PATCH /vulnerabilities/{id}/workflow` | accepts query params, not JSON body | frontend already uses params ✓ | — |
| `GET /openapi.json` path | `/api/v1/openapi.json` | frontend does not consume it | No tooling drift check today. |
